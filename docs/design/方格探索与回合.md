# 方格探索与回合

2026-10-12 用户要求：FU 使用类似 AAF 的方格地图探索，不使用英尺或米；每个场景由 GM 配置每轮移动格数，玩家按回合行动。此合同替代早期无约束 Token 拖动方案。

## 交互

- 探索地图始终显示正方形网格。背景完整放在棋盘内，背景、网格、Token 使用同一坐标面；可缩放、拖动视野并一键查看全图。页面本身不滚动。
- GM 在准备场景时设置列数、行数、每轮移动格数及是否允许斜走。默认 24 × 14 格、每轮 6 格、允许斜走；横、竖、斜走均每格消耗 1。关闭斜走后按横竖路径计数。不附加 FU 原书没有要求的距离、地形或阻挡计算；通行由 GM 裁定。
- GM 在“开始探索”面板选择公开 Token 对应的角色并安排顺序，默认选择玩家角色。相同角色多个 Token 共用一个回合和额度。没有角色或没有公开 Token 时引导先放置。
- 当前角色的持有人选择自己的 Token，再点击目标格或拖动落格；方向键可逐格移动。显示可达范围、移动预览、当前轮次、行动者、剩余格数和结束回合入口。
- “结束回合”由当前角色持有人或 GM 操作。依序轮换，全体结束后进入下一轮并补满额度；移动用完不会自行跳过行动者。GM 可明确打开“调整位置”，免费布置任何 Token，不改变该角色已用额度。
- 各场景保存独立轮次和额度；切换场景只暂停原场景，返回时继续。冲突进行中不能移动探索 Token 或开始探索；先结束冲突。GM 结束探索后可更改网格、移动规则或 Token 名单；再次开始为新一轮探索。

## 合同与服务器

- `Scene.grid`：`columns`（4～60）、`rows`（4～60）、`movePerRound`（1～60）、`diagonal`。旧场景缺省时应用默认值。
- `Scene.exploration`：`active`、`round`、`order`（角色 ID）、`current`、`spent`（按角色的已用格数）。此字段只能由服务器的探索命令维护，`scene.save` 不接收客户端回写的运行状态。
- 为兼容存档，Token 的 `x/y` 继续保存 0～100 百分比；显示、保存和移动均映射到整数格中心。旧 Token 初次显示按最近所在格落位，不丢弃角色或原场景。
- `token.move` 保留原接口，地图移动额外要求 `expected` 场景版本；`adjust` 仅 GM 可用。服务器核对当前开放场景、Token 所有权、可见性、探索状态、当前行动者、剩余额度、目标格及版本；旧接口不能绕过回合限制。
- `exploration.start/endTurn/stop` 使用场景 ID 和版本；开始时携带去重角色顺序。重复提交或旧页面提交必须被拒绝，不能连跳回合。按房间串行、原子保存并广播最新视图。
- 进行中的场景不允许改网格、模式、Token 名单/隐藏状态或将参演角色转为私密/删除；需先结束探索。改背景、备注等不重置额度。玩家视图过滤不可见角色和 Token 关联的回合资料。

## 验收

共享格子计算、斜走与横竖计数、超额拒绝、他人/隐藏/非当前角色拒绝、GM 调位、重复提交、整轮重置、多 Token 共额度、场景隔离、旧存档、重启持久化；浏览器检查拖动/点击、地图缩放与 Token 对齐、轮次提示以及桌面/窄屏无整页滚动。
