# 命刻与冒险日志 · 0.1.2

依据 2026-10-12 的用户要求，网站辅助战斗、探索、演出和记录；物语点改写故事的具体内容由玩家与 GM 通过聊天约定。没有增加剧情裁定流程。设计和数据合同见 [命刻与冒险日志](design/命刻与冒险日志.md)，操作说明见 [使用与部署](../deploy/使用说明.md)。

## 本次交付

- JRPG 风格 SVG 命刻：金色外环、分格填充、中心读数，以及目标／危机／调查／旅程四种外观。名称、用途与数值同时展示，不只依靠颜色辨识。
- 主要命刻常驻桌面右侧记录栏顶部；其他公开命刻用小盘展示，可展开或点击查看详情。手机端在工作区前方显示紧凑卡片，不悬浮遮挡舞台或地图。
- GM 创建与编辑命刻，手动加减或直接选择刻度，指定主要命刻、设为私密、归档与恢复。4～12 格；刻满不触发剧情。切换主要命刻不会修改各自的进度。
- 普通聊天有独立输入框，保留当前舞台发言；讨论物语点不会执行剧情脚本，也不会推进命刻。
- 独立冒险日志：线索／纪要、标题和正文搜索、公开／私密、编辑、归档／恢复、导出 Markdown。聊天中的“存为线索”生成可编辑草稿。日志不随最近 300 条聊天记录截断。
- 玩家维护自己的日志，GM 可维护全部；私密条目只发给作者与 GM。编辑检查版本，防止旧表单覆盖新内容。旧世界缺少日志字段时补空列表，保留原命刻、刻度和资料。

## 验收证据

类型检查与生产构建通过。本轮运行了世界逻辑、记录专项和 HTTP 接口三组测试，共 19 项通过。记录专项覆盖 GM 权限、主要命刻与私密边界、说明修改保留当前刻度、刻满不触发剧情、聊天／掷骰／回合／物语点不推进命刻、日志作者与版本冲突、归档恢复、聊天截断后的线索保留，以及旧世界兼容。

在本机网页以独立 GM 和玩家身份实际完成：

1. 创建三种不同命刻并手动设为 3/6、2/4、5/8；玩家端显示相同内容且没有调节控件。
2. GM 将调查命刻设为主要命刻，玩家立即同步；归档后其他命刻接替展示，恢复后保留原值。
3. 舞台发送旁白后继续普通聊天，舞台台词保持原内容；把聊天摘录为线索并保存，玩家能读取公开线索且没有编辑他人条目的按钮。
4. 检查 1280×850 桌面与 390×844 窄屏布局，主要命刻和说明可读，次要命刻与工作区分开排列。
5. 实际解压三种发行包并核验摘要，程序包与规则包合并后匹配完整包。将已核验程序合并更新至原预览目录，更新前后 data 文件摘要一致；从发行文件重启后，GM 身份、三只命刻、舞台旁白与线索日志均恢复。
