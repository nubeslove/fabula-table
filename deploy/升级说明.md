# Windows 保留存档升级

适用：已部署的最终物语 0.1.6、0.1.7、0.2.0、0.2.1。升级到 0.2.3；此前升级失败且已经回退的服务器，也使用此包。

1. 将 `fabula-table-upgrade-0.2.3.zip` 解压到一个**新文件夹**。不要先覆盖原部署。
2. 右键 `upgrade-windows.cmd`，选择“以管理员身份运行”。
3. 输入原 FU 部署目录，例如 `D:\FabulaUltima`。应选择里面有 `app`、`.env`、`data` 的那一层，不是 `app` 本身。
4. 等待备份、路径权限修复、替换和启动检查完成。程序会先确认后台任务完全停止；新版启动最多等待 60 秒。旧进程已经手动关闭也可以直接运行升级器，成功后会启动新版。仍使用原 IP、端口和 `/fu/` 入口，不用重填。
5. 玩家刷新网页。先注册统一账号；在大厅找到原世界，选择“认领旧身份”，输入原来在该世界使用的名字和登录口令。原浏览器仍保留登录时，可点击世界上方“去大厅绑定账号”，直接绑定已验证的身份。

认领只绑定登录身份，世界编号、GM 权限、人物 ID 与归属、场景、手记、命刻和上传素材全部保留。不同世界的旧身份可分别绑定到同一账号。新账号不能仅凭同名或世界密码获得原 GM 权限。

如果误点“进入世界”生成了空的玩家身份，仍可回大厅选择“认领旧身份”。若新身份已经创建人物或日志，程序不会自行合并或丢弃它们；请由 GM 先整理归属，或使用尚未加入该世界的账号认领。

GM 在“世界设置”中设置世界密码，留空为开放。已加入的成员可以直接返回；世界密码用于新成员加入。旧版本世界没有世界密码，升级后在大厅列为开放，请 GM 按需设置。原个人口令不会变成公开世界密码。

## 备份和更新边界

- 完整升级前备份位于原部署目录 `backups/before-0.2.3-时间/`，含原程序、配置和数据副本。请保留此目录，里面也有私密资料和账号密钥。
- 只替换 `app` 和启动说明/脚本。原 `data`、`.env`、`runtime`、日志、服务器密钥均不覆盖。
- 使用原后台任务时，会为 LOCAL SERVICE 补充安装路径上各父目录本身的属性读取与路径通过权限，用于修复桌面安装的 `EPERM / lstat`。此授权不继承到子目录和文件，不增加目录列表、其他文件读取或写入权限。原父目录权限保存在备份内 `service-path-acl-before.json`；程序回退时保留这项启动权限修复。
- 自定义 `FU_DATA_DIR` 也会按原配置读取并备份。自定义 `FU_PUBLIC_DIR` 或链接目录会明确停止，请先核对实际部署路径，不会猜测后覆盖。
- 只停止这个部署目录对应的 FU 进程/计划任务。新版启动失败会恢复原程序。云安全组和其他网站不变。
- 备份空间需容纳原世界与上传素材的副本。此升级包已含重排后的官方文本，**不需要再下载官方规则包**。
- 如果服务器原先用 `start.cmd` 手动启动，升级后会从原目录隐藏启动；原先用部署向导安装的计划任务则沿用计划任务。
- 离线维护可在服务已停止后执行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File upgrade-windows.ps1 -TargetDirectory "D:\FabulaUltima" -NoRestart`；完成后自行按原方式启动。

需要恢复时，先停止 FU，再使用备份中的 `app` 与启动文件恢复程序。`data` 备份是升级前快照；仅在确实需要回到升级前进度时才用它恢复实际数据目录，以免丢失升级后的跑团记录。备份中的 `upgrade.json` 记录了原数据目录。

## 如果仍提示启动失败

升级窗口会显示实际连接错误、本次启动日志，并给出 `backups/before-0.2.3-时间/upgrade-report.txt` 的完整位置。该报告记录这次启动的服务错误、后台任务状态以及回退后的检查结果，不读取或列出 `.env` 内容。

- 显示“已确认旧版 0.1.6 恢复运行”：旧网页仍可用，世界数据未被覆盖。将报告中的文字交给维护者继续排查。
- 显示“原程序文件已恢复，但旧版启动未通过检查”：文件已回退，服务尚未确认可用。请同时查看原部署目录 `logs/server.log` 的最后几行；不要删除 `data` 或拿空部署覆盖原目录。
- 0.2.0 的旧提示没有保存具体检查错误；若手头只有旧包的失败记录，先查看 `logs/server.log`。不要把含密码的 `.env` 或完整世界备份发到聊天中。

0.2.1 修复任务退出等待和慢启动误判，并补齐失败原因记录。0.2.2 根据服务器实际诊断修复安装目录位于 Administrator 桌面时，后台账户无法解析父目录导致的启动失败。

升级后若需要启用网页更新，请在原目录右键 deploy-windows.cmd 以管理员身份运行一次。它会新增服务器管理密码、配置更新来源与后台所需权限；原数据继续保留。全新安装直接使用完整包的 install.bat。
