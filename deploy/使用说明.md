# 最终物语 · 独立物语桌

这是独立网页，不需要玩家安装 EXE。程序、规则文本和世界素材放在不同目录；不会加载共坠群星的数据。

## 选择发布包

- **全新安装：使用 `fabula-table-0.2.4.zip`**。包含程序、规则文本、在线更新与启停脚本。解压到新目录，双击 `install.bat`；不要合并到旧目录。这次将创建新的账号库与空世界列表，旧后台任务由新目录接管。
- `fabula-table-upgrade-0.2.4.zip`：另供需要保留旧部署数据的用户离线升级，详见同包《升级说明.md》。
- `fabula-table-program-0.2.4.zip`：仅程序，不含官方文本。
- `fabula-table-rules-0.2.4.zip`：独立官方文本包，用于补装或更新规则资料。

升级向导先备份，再替换程序与官方文本；保留 `data`、`.env`、`runtime`、原 IP、端口和入口。每个包都有文件校验清单。玩家使用浏览器按需加载，32 份规则资料不会在进入世界时全部下载。升级包已包含官方规则，无需另下载规则包。

## 本机使用

Windows 本机试用安装 Node.js 22+ 后，双击 `start.cmd`；脚本会检查本目录的 runtime、标准安装目录及 PATH，并读取已有 `.env`。没有部署配置时仅供本机访问 `http://127.0.0.1:3340/`。Linux / macOS 仍可使用 Node.js 20+ 运行 `bash start.sh`。先注册统一账号，随后在大厅创建世界；本机建房钥匙可留空。

## 复制到 Windows 服务器（当前用户的部署方式）

0.1.6 起提供专用部署向导。旧 0.1.5 的 `start.cmd` 只用于本机预览，依赖预装 Node，也不会读取 `.env`；服务器请更新后使用下面的入口。

1. 将完整包解压到新的固定目录，例如 `C:\FabulaUltima`。不要在压缩包内部直接双击脚本，也不要复制旧目录的 `data` 或 `.env`。
2. **双击 `install.bat`**，在 Windows 管理员权限提示中选择“是”。选择 `1`（公网 IP / 域名直连），端口可直接回车采用 `3340`。
3. 从云服务器控制台复制这台服务器的**公网 IP**，粘贴到“公网 IP 或完整网站地址”提示处。例如填 `203.0.113.42`，最终入口是 `http://203.0.113.42:3340/fu/`；示例 IP 必须换成自己的。
4. 向导检查现有 Node.js 22+；没有时从 `nodejs.org` 下载官方 Node.js 24 LTS 的免安装环境，核对 SHA-256 后只取运行程序与许可证，放在 `runtime`。这是服务器首次准备，玩家不需要安装或下载 Node。
5. 向导保存 `.env`，生成建房钥匙，注册 `FabulaUltima` 开机后台任务，并为该程序的指定端口添加 Windows 防火墙规则。后台以 Local Service 身份运行，世界和日志目录拥有所需写权限；安装路径的父目录仅补充目录属性读取和路径通过权限，保证放在用户桌面时 Node 也能解析入口。该权限不继承到其他文件，原父目录权限保存在 `service-path-acl-before-编号.json`。
6. 在**云服务器控制台的安全组／云防火墙**中，允许入站 **TCP 3340**（换了端口就填写所选端口）。向导不能操作云平台安全组。
7. 部署结束显示完整网址。在自己电脑上打开该网址；GM 建房时从服务器 `.env` 复制 `FU_CREATE_KEY` 等号后的内容作为建房钥匙。玩家加入已建好的世界不需要建房钥匙。

**不会自动认定公网 IP。** 网卡常显示内网地址，公网映射由云平台管理；填写的是玩家要访问的公网地址。配置中的 `FU_HOST=0.0.0.0` 表示监听服务器接口，不是玩家访问网址，也不应填成公网 IP。

如果已有 HTTPS 站点，选择 `2`，输入完整站点地址（例如 `https://trpg.example.com`），再把原站点 `/fu/` 转发到 `http://127.0.0.1:3340`，保留 `/fu` 路径。模板 `nginx-fu.conf` 可供参考，实际端口需一致；不会自动改写共坠群星已有站点。IP 直连使用 HTTP，长期使用可接入 HTTPS；HTTP 下浏览器可能限制“一键复制”，可以手动复制显示的邀请链接。

部署后关闭命令窗口或退出远程桌面不影响后台任务。**停止：双击 `stop.bat`；恢复：双击 `start.bat`。** 停止后开机自启和自动更新均暂停，直到再次启动。两者只处理本安装目录的 FU，不停止其他 Node 程序。运行日志在 `logs/server.log`，启动失败的具体原因也会写到 `startup-report.txt`。服务器日常使用 BAT，不要再同时运行本机前台入口 `start.cmd`。

## 网页更新与每日自动更新

首次安装后，用记事本打开服务器目录的 `.env`，保存 **`FU_ADMIN_KEY`** 等号后的管理密码。它与 `FU_CREATE_KEY` 建房钥匙、账号密码、世界密码分开，只给服务器管理者使用。

在任意电脑打开物语大厅 → **服务器管理** → 输入管理密码 → **检查更新** → **更新并重启**。界面会显示当前版本、新版本说明与进度；重启期间自动重新连接。手动更新前，请让玩家返回大厅，世界连接数为零才可开始。

`FU_AUTO_UPDATE=1` 默认开启自动更新：每天检查正式版，所有世界无人、且连续空闲 10 分钟才执行。联网检查时有人重新进房会推迟更新；网络错误等待一小时再试，不影响当前服务。改为 `0` 后重启可停用自动更新，手动更新仍可用。

更新从 `nubeslove/fabula-table` 的正式 GitHub Release 下载完整 ZIP，核对 SHA-256 和逐文件清单后，仅替换 `app` 中的程序与规则文本。会先保存当前程序、账号、世界、素材和配置的备份。数据仍使用本目录的 `data`，不会把新程序包中的空白数据覆盖进去。新版启动失败会恢复原程序和数据；中断后下次启动会先恢复。

备份保存在 `updates/backup-*`，需要预留当前程序和数据副本的空间。它们不公开，也不上传 GitHub；确认新版使用正常后，可自行清理较早的备份。安装引导器的协议如果有大版本变化，界面会提示使用新的安装器，不会强行套用不兼容更新。

以后修改 IP／端口或重新配置后台任务，可右键 `deploy-windows.cmd` 以管理员身份运行。`install.bat` 专用于空目录的新安装，不会抹掉已有数据再装一次。

安装失败会显示具体原因，例如无管理员权限、端口已被其他程序占用、运行环境下载失败或后台启动检查未通过。脚本只验证服务器本机可响应；最终公网是否畅通，需要另一台电脑实际访问确认。

## 复制到现有 Linux 服务器

1. 将压缩包解开到固定目录，例如 `/opt/fabula-table`。服务器需要 Node.js 20+；自动压缩音视频还需要 FFmpeg（Ubuntu / Debian 可使用系统软件源安装 `ffmpeg`）。
2. 运行 `sudo bash deploy.sh`。脚本生成独立 `.env`、建房钥匙与 `fabula-table` 服务，不覆盖已有世界。建房钥匙保存在 `.env` 的 `FU_CREATE_KEY`，只交给需要建房的 GM。
3. 把 `nginx-fu.conf` 的两个 location 段加入现有 HTTPS 站点的 server 段，检查配置通过后重载 Nginx。由于既有服务器配置未知，本包不自动改写它。
4. `.env` 加入 `FU_PUBLIC_URL=https://你的域名`（只有域名，不带 `/fu`），重启服务。访问 `https://你的域名/fu/`。

端口默认为 3340，入口为 `/fu/`，绑定本机回环地址。端口或入口改变时，要同时修改 `.env` 与对应 Nginx location。请通过现有 HTTPS 站点接入，不要把建房钥匙写进前端文件。

服务器托管独立房间和素材；本版没有开通任何外部对象存储。GM 与玩家均无需 GitHub 或对象存储账号。已有服务器安装过程尚需在你的实际环境中执行。

## 一次跑团的流程

- 每人注册一次统一账号。GM 在大厅创建世界，可设置世界密码，留空即开放。玩家点击世界后按需输入密码；已经加入的世界可直接返回。刷新会恢复当前世界，顶栏“返回大厅”可切换世界，不退出账号。
- 从旧版本升级：注册账号后先选择原世界条目的“认领旧身份”，用原名字与口令验证。仍保留原浏览器登录的用户可从世界上方“去大厅绑定账号”接续。认领后原 GM 权限、人物归属和世界数据保留。旧世界默认开放，GM 可在世界设置添加密码。
- 创建世界和“世界设置”均可勾选高度奇幻、科技奇幻、自然奇幻、测试与补充、其他可选资料。启用后相应职业和能力出现在建卡中；关闭不删除既有人物的选择。
- “人物”自动建卡包含核心 15 职业与启用的扩展职业。身份、HP／MP／IP／物语点固定在上方；人物、属性、职业、装备、羁绊、扩展资源、自定义和立绘分标签。“扩展资源”可搜索能力、法术与可选条目，加入后仍能修改。复杂前置条件由 GM 确认。“自定义”保留数值修正、覆盖与私设职业／能力。
- GM 上传背景、音乐、立绘，在“场景”准备演员、表情、台词和探索 Token。点击“打开”才开始当前幕。数字键 1～6 快速换角；输入框中不会触发。每个角色的台词草稿各自保留。台本中的“默认立绘”会恢复默认表情；长台词可在对话框中滚动阅读。
- 玩家点击能力只发声明，再单独掷骰。GM 按实际结果输入 HP 增减；其他资源可由持有人调整。任何能力按钮都不会自动计算伤害或替主持人判定。
- “冲突回合”先勾选本次参战者，默认选中玩家角色与当前场景中的人物，也可全选、清空或仅选本幕人物。双方各选至少一人，指定先手后开始；旁观 NPC 可留在舞台，只有参战者计入行动。由 GM 选择行动者并结束行动。“命刻”可创建公开或私密进度，填满不会自动触发剧情。
- “规则书”以文本提供核心、扩展与可选规则。可按页查看并在当前资料内搜索；保留原文件名与页码供本地原稿校对。插画页不打包为整页扫描图。

## 单屏游玩

进入房间后，舞台始终保留在屏幕内。演出模式常驻台词输入；冲突模式从场景上沿“台词”按钮展开。顶部的人物、场景、工具、日志、规则书、素材入口会打开可关闭抽屉，Esc 可回到舞台；窄屏从右上角功能菜单进入。首次建卡使用弹窗，可稍后再从人物入口创建。长表单和规则正文只在面板内部滚动。

点击右上角聊天图标可展开／收起聊天栏。演出设置在台词输入上方，角色和草稿切换不离开舞台。舞台台词右上角可收起，方便看清场景；新台词到来时会展开。背景按完整画幅显示，探索标记与地图一起缩放。

### 方格探索（0.1.7）

1. GM 在“场景”中新建或编辑场景，将形式设为“探索地图”，选择背景，填写地图行列数、每人每轮移动格数及移动方式。只按格数计量，没有英尺、米或移动速度换算。
2. 添加人物 Token，保存并打开场景。GM 先自由拖动摆位；旧 Token 会自动落到对应格中心。若仍有冲突进行中，先在冲突设置中结束冲突。
3. 点击地图底部“开始探索”，勾选参与者，用上下箭头安排先后，开始第 1 轮。默认选择公开 Token 对应的玩家角色；可加入 NPC，同一角色的多个 Token 共用额度。
4. 当前角色持有人选择 Token，点击目标格、拖动落格或用方向键逐格移动；范围高亮和预览显示消耗。默认横、竖、斜走都算 1 格；禁用斜走后，按横竖路径累计。障碍与通行由 GM 裁定。
5. 完成后点击“结束回合”，轮到下一人；全体结束才进入下一轮并补满格数。用尽移动力不会自动跳过回合，玩家仍可说明探索行动。
6. GM 的“调整位置”允许免费摆放 Token，不改变本轮已用格数。“回合顺序”弹窗可结束探索；结束后才可改网格、额度和 Token 名单。切换场景会保留原场景的轮次与剩余格数。

地图右上角可缩放或查看全图，放大后拖动空白处移动视野。台词输入区默认收起，随时从上方“台词”打开。0.2.0 已包含方格探索功能。

## 目录、战斗与资料

- 场景以紧凑条目存放。编辑场景时填写“目录分类”，可以使用已有分类或输入新名称；新建场景默认沿用当前选中的分类。左侧目录、名称搜索与形式筛选组合使用。旧场景放入“未分类”；GM 世界手记与导出记录固定在底部。
- 开始冲突后主舞台显示二维对峙：我方在左下，对方在右上，沿用本幕背景。上传的立绘／Token 按完整比例展示；没图时用带名字的标记。每侧一组最多四人，可翻组查看更多角色。
- 点击角色查看；GM 点击“让此角色行动”指定当前行动者。底部“能力”“掷骰”“调整数值”在向上滑出的抽屉中操作，舞台和聊天仍可使用，Esc 关闭。能力按来源筛选并可搜索；声明、骰子和数值调整分步进行。冲突设置可结束冲突。玩家不能代操作他人或修改 HP，也看不到 NPC 的隐藏数值。
- 规则书按核心与扩展分组，左侧分级目录、右侧正文、固定底部导航；窄屏用“目录”展开。可搜索跨原书换行的词语。HTML／CHM／DOCX 扩展重建语义章节、条目与表格，PDF 保留来源页和页内标题定位。“原始文本”保留提取稿。死灵术士的独立 PDF 存在字形映射问题，阅读页明确注明采用同资料集的可读 CHM 译稿，原 PDF 留在资料目录供核对。
- 世界素材使用文件条目，可按名称和图片／视频／音频筛选，点击预览。“邀请与预下载”单独一页；在素材条目旁勾选“允许预下载”后复制链接。上传选项中的清晰度复选框仅影响随后上传的图片。

战场随宽度分组显示人物与命刻：常规屏幕每方最多四人，窄屏每方两人，使用翻组按钮查看其余成员，不把整个舞台缩成小字。

## 人物分类

“人物”分为“玩家角色”和“非玩家角色”两个目录，显示各自数量，可按名称、身份或持有人搜索。新建按钮跟随当前类别。编辑、登场和退场保留在紧凑条目上；GM 可在人物卡的“人物类型”中更改归类，友方 NPC 仍属于非玩家角色。

## 命刻、聊天与线索

命刻横排铺在场景上沿的可用区域，不占用聊天栏。点击某个刻度盘直接打开该命刻；右端“⋯”管理全部命刻。GM 可在窗口中创建、编辑、手动调整、勾选“优先显示”或归档。优先显示可选择多个，排在其余命刻前面；同组内沿用原顺序，没有优先项时全部按原顺序排列。填写名称和“这在记录什么”，让玩家知道每个盘对应的事件；目标、危机、调查、旅程只是外观分类。

GM 可按加减按钮，或直接选择 0～上限的刻度。刻满只显示“已填满”；掷骰、回合、聊天和物语点都不会自动改变命刻。归档可恢复。私密命刻仅 GM 可见，不进入全团命刻横条。每项显示名称、类别与进度；横条放不下时用左右箭头翻组，收起聊天后会利用更多宽度并排显示。

冲突命刻绑定到指定冲突场景，GM 选择上半场左侧或下半场右侧。点击半场的“＋”即可创建，多个命刻可翻组。它们不挤占全局横条和聊天。GM 悬停或键盘聚焦命刻时出现“＋／−”快捷按钮；触屏始终可见。

右侧分为系统日志、场内聊天、场外聊天、掷骰、战斗日志五类。场内默认使用自己的角色身份；场外使用账号在世界中的成员名字，旧身份绑定后保留原名字。创建人物、进出世界归系统，能力声明、资源变动与回合归战斗。聊天不会替换舞台台词。物语点改写故事由大家讨论，再手动调整数量。

“日志”页独立保存线索和纪要，可按标题／正文搜索、编辑、归档／恢复，以及导出当前列表。聊天记录下的“存为线索”会打开摘录草稿，确认后才保存。玩家维护自己的条目，GM 可维护全部；私密条目仅作者与 GM 可见。独立日志不受最近 300 条聊天记录的截断影响。

## 素材与预下载

- 上传图片时转为 WebP 并控制尺寸，透明区域会保留。GIF 与动画 WebP 保留动画。含小字的地图可勾选“保留原尺寸与清晰度”，保留已有 PNG／JPEG／WebP；避免缩图使规则或地图文字变糊。
- 有 FFmpeg 时，视频会压缩为 WebM（VP9 / Opus），音频转为 Ogg Opus；如果转换后反而更大且原格式可在网页播放，则保留较小的原文件。不支持的字幕或媒体文件会报错，不静默丢弃。
- 没有 FFmpeg 时可使用已有 WebM / MP4 和 MP3 / Ogg；部署者安装后即可自动压缩。单文件上限 100 MB，不将大文件放进世界 JSON。
- GM 勾选“允许预下载”，将预下载链接发给玩家。链接只开放选中的素材，不提供世界台本、人物数值或 GM 手记。
- 玩家在正式跑团使用的浏览器、设备和站点地址中打开链接，点击开始。完成的文件会缓存在浏览器；暂停或失败后重试会跳过完成项。续传以文件为单位，不保留半个文件。
- 正式进房自动补充缺少的素材，相同内容只下载一次。缓存受浏览器存储空间限制；清理浏览器数据、换域名、换浏览器或换设备后需要重新下载。
- 浏览器禁止存储或空间不足时，房间仍显示本次已下载的素材，并提示它们未全部缓存；再次进入可能重下。预下载必须成功存入浏览器才会计为完成，保存失败时显示错误，处理空间或权限问题后可重试。
- 更换预下载链接会阻止旧链接继续下载；已经发给玩家的文件无法远程收回。

## 更新、备份与恢复

程序在 `app/`，官方文本在 `app/public/official/`，世界、素材和登录凭据在 `data/`，部署配置在 `.env`。**更新只替换程序／官方资源，不覆盖 data 与 .env。**

完整备份时停止 `fabula-table` 服务，复制整个 `data/` 与 `.env`，再启动服务。恢复到相同版本的程序目录、保持目录权限后即可读取原世界和身份。不要公开这些备份。

“导出世界记录”只导出角色、场景、命刻、独立冒险日志、最近 300 条聊天记录等 JSON，方便阅读或迁移；它不含素材二进制、密码或会话签名密钥，不能代替完整备份。当前界面没有导入世界记录按钮。
