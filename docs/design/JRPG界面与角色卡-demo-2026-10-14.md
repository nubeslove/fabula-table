# 深蓝金色物语桌 · 独立交互 Demo

## 本轮范围与已确认选择

用户确认先完成 demo，再接入正式功能。正式 0.2.5 只发布聊天快捷键、未读提醒、单／双骰；本 demo 不读写世界、不修改正式角色合同。

风格：深蓝、克制金色、轻透面板；舞台优先、根页面不滚动。展示演出／探索／冲突切换，聊天、掷骰、非模态角色／行动抽屉。角色卡增加泽尼特、装备与背包、自定义武器以及可读的法术条目。

## FU 规则核对（用户提供的本地资料）

来源目录 `E:/TRPG/FU`。复用已转换网页文本，核对对应原书来源和页码，不再扫描整本 PDF。

- 核心规则书印刷 122 页（PDF 124）：主手、副手、防具、饰品四个装备栏。双手武器占两个手部栏位；背包中的物品不提供装备效果。
- 印刷 69 页（PDF 71）：同类别双武器可分别攻击，失去多重、伤害 HR 视为 0，不适用于自由攻击。印刷 234 页“灵巧双手”支持不同类别；不自动代算攻击。
- 印刷 197 页（PDF 199）：守护者“双重盾牌”允许主手持盾；两面盾牌同时提供好处，并可合为格斗类别双手近战武器，命中 MIG+MIG，伤害 HR+5 物理，并加防守掌握 SL。基础规则并非所有角色无条件双盾；界面必须支持技能与私设例外，不能只用一个“持盾”勾选框。
- CHM 的“自定义武器 Custom Weapon”第 2、3 节：基础 300 泽尼特，双手且不能受灵猴握影响，选类别与近／远程，命中 DEX+INS 或 DEX+MIG，基础 HR+5 物理，三份定制名额；精准 +2、元素改变伤害且 +2、强力通常 +5（重型 +7，带职业要求）；迅捷占两份、可变形增加 100 泽尼特。示例“星轨刃”采用精准／元素·光／强力，故命中 DEX+INS+2、HR+12 光，职业剑、双手。
- 原核心 2023 译本与用户截图存在版本差异：核心召唤费用 40，截图 30；核心加速为两次额外动作，截图为一次回合末自由攻击／咒语；核心抽取精魂为 HR+15，截图精神汲取为高值+20。Demo 的三个示例法术明确以用户卡面样例为来源，避免将不同版本静默拼接。正式接入需要记录规则版本与来源，允许 GM 私设覆盖。

## 信息结构与空间预算

以 1440×900 为主，验收 1280×720：顶部 52px 导航、64px 命刻条、底部 86px 队伍操作条；右侧聊天 300px，余下全部为场景。小窗口聊天可收起，仍有未读入口。画面不因命刻或条目增加而向下生长。

战斗快捷行动抽屉从舞台底部升起，桌面高度 242px，保留敌方和上半场命刻；完整角色卡供主动阅读，桌面高度为 490px 与“舞台高度减 60px”中的较小值。两者均不加遮罩、不设模态焦点陷阱，聊天仍可操作。角色名、HP／MP／IP／物语点／泽尼特和关闭键常驻。完整卡分为三页：

1. 概览：四属性骰、身份与羁绊、当前装备摘要。
2. 能力与法术：左侧可搜索紧凑目录，右侧唯一选中详情，MP／目标／持续时间、技能来源和效果层级清晰。
3. 装备与背包：四栏位独立显示；背包紧凑条目；选中物品详情。可切换双武器／双盾／自定义双手样例；双盾说明技能来源，双手以连接标记表现占用。私设覆盖有显式标注，不冒充基础规则。

快捷行动与完整角色卡共用非模态容器，但采用不同高度与信息结构。快捷层显示攻击／防御／装备／物品、三个常用法术与声明预览；“阅读条目”可进入完整详情。声明只写入 demo 战斗日志，不扣 MP／HP、不卡回合。

## 视觉与交互

- 背景 #081321，面板 #112339，文字 #e7edf3；金色 #d8bc7f 只用于当前项、名称和命刻；HP 青绿、MP 蓝、IP 紫，始终附文字。
- 正文 14px，数据 16–24px，章节 18–24px；中文标题用系统宋体衬线，正文用系统 UI 字体，不下载字体。
- 主要间距 8／12／16px，场景零外边距；细金线与少量角饰替代多层容器。
- 轻量 SVG 场景示意；角色复用本地 AAF 生成立绘，转压缩 WebP，仅作 demo 演示素材。其余角色用有姓名的 2D token；不冒充新绘制成品。
- 可操作：切模式、点角色发言、探索格子移动与回合补充、冲突选角色／动作、命刻加减、聊天 Enter／Shift+Enter、单／双骰、法术搜索详情、换装与私设记录。
- Esc 收起最近面板；可见焦点；减少动态效果时禁用滑入／缩放。窄窗口收纳次要导航，不通过整体缩字适配。

## 制作顺序与验收

1. 聊天 0.2.5 发布到既有 GitHub 更新通道。
2. 实现独立静态 demo 和本地预览，不依赖账号、服务器世界或外部资源。
3. 浏览器检查三场景、法术详情、双武器／双盾／双手占用、抽屉与聊天并存；1280×720 与更窄窗口检查根滚动和按钮可达。
4. 保存截图、试用入口及局限，等用户审阅后再接入正式角色数据。
