# 最终物语 · 独立物语桌

独立于共坠群星的 FU 网页跑团桌，用于半手动战斗、探索、演出和冒险记录。命刻由 GM 手动管理；物语点如何改写故事，交给全团聊天讨论。玩家不用安装 EXE，也不用第三方云服务账号。

## Windows 安装与更新

从 [GitHub Releases](https://github.com/nubeslove/fabula-table/releases/latest) 下载完整的 `fabula-table-版本.zip`，解压到新的固定目录，例如 `C:\FabulaUltima`。双击 **install.bat**，允许管理员权限，输入服务器公网 IP 和端口。安装器会准备运行环境、接管旧 FU 后台任务，并在新目录创建空账号库与空世界列表。

| 文件 | 用途 |
| --- | --- |
| `install.bat` | 全新安装，运行后在后台启动 |
| `start.bat` | 启动后台服务，恢复开机自启 |
| `stop.bat` | 停止本目录的服务，暂停开机自启；保留数据 |
| `update.bat` | 单独下载后放入安装根目录，自动下载正式最新版、备份并升级，不受网页连接数限制 |
| `deploy-windows.cmd` | 在已有目录修改 IP／端口或重新配置后台任务 |
| `start.cmd` | 旧的本机前台试用入口，服务器日常启停使用上面两个 BAT |

大厅 → **服务器管理** → 输入 `.env` 中 `FU_ADMIN_KEY` 的值，可以检查版本、阅读发行说明、更新并重启。管理密码与建房钥匙、世界密码分开。默认每天检查正式版本；只有所有世界无人、且持续空闲 10 分钟才自动更新。手动更新同样要求玩家先返回大厅。

在线更新备份并保留当前账号、世界、上传素材和配置，只更换程序与官方规则文本。启动检查失败时恢复上一版；中途断电时，下次启动先恢复。备份在本机 `updates/backup-*`，不上传 GitHub。停止 BAT 后，自动更新也停止，不会自行启动服务器。

网页更新被后台世界连接阻挡时，可下载 [update.bat](https://github.com/nubeslove/fabula-table/releases/download/v0.3.3/update.bat)，放到与 `app`、`data`、`.env` 同级的安装根目录，双击并允许管理员权限。它自动下载 GitHub 最新正式升级包，校验 SHA-256 后调用包内的 Windows 升级流程，停止本目录 FU、备份、替换并检查启动；保留现有世界、账号、素材、配置和运行环境。下载失败不会停止原服务。此入口的备份位于 `backups/before-*`，日志位于 `logs/manual-update-*.log`，下载缓存位于 `.fu-downloads`。运行期间会断开所有世界连接；更新成功后刷新浏览器。

单文件升级入口已用隔离的 0.3.0 安装副本验证升级至 0.3.3、启动检查、备份和数据保留，并验证损坏下载拒绝执行及同版本跳过。复现脚本为 `scripts/verify-manual-update.ps1`；测试下载使用本地发行包替身，不连接或修改用户服务器。

公网 IP 需要手动填入；云控制台仍需开放所选 TCP 端口，默认 `3340`。完整操作见[使用说明](deploy/使用说明.md)。

本仓库包含程序、已转换的规则文本和构建代码。房间存档、上传素材、账号、口令、服务器密钥和本地运行记录均不在仓库内。首次正式发行是 **0.2.3**。

## 开发与验证

使用 Node.js 22+。安装依赖后，两个终端分别运行 `pnpm dev` 与 `pnpm dev:ui`，浏览器打开 `http://127.0.0.1:1540/`。

`pnpm check` 做类型检查。`pnpm build` 生成独立网页和无需服务器安装依赖的 Node 服务。`pnpm test` 检查建卡、权限、舞台、命刻、回合、素材缓存失败处理、持久化与 HTTP 接口；HTTP 验证需要先构建。`pnpm package` 同时生成保留存档升级包、首次部署完整包、程序更新包、官方规则文本包，版本统一来自 package.json；不包含 data、output 或原始附件。已部署 0.1.6 的 Windows 服务器使用升级包，详见升级说明。

0.2.0 采用独立站统一账号和世界大厅。新成员输入 GM 设置的世界密码加入，留空即开放；原成员可直接返回。旧世界先认领原身份，保留 GM 权限与人物归属。世界扩展开关控制新增职业与能力，已有选择不会因关闭扩展而被清除。正式部署与本机预览数据彼此独立。

## 目录与边界

- `src/shared`：独立数据合同、核心职业与衍生计算。
- `server`：认证、房间保存、角色权限、分身份视图、事件同步与素材服务。
- `src/components`：人物编辑、演出、探索、跑团工具、资料阅读与预下载。`App.tsx` 装配页面。
- `src/lib/media.ts`：图片准备、按内容散列的浏览器缓存与缺失文件下载。
- `public/official`：转换后的 UTF-8 资料、稳定条目 ID 和带内容散列的资源文件。读取按资料加载，不载入原始 PDF。
- `scripts/import-*.py`：只读用户 FU 资料，生成核心目录和网页正文；源目录及审计提取位置记录在脚本中。
- `deploy`：独立服务启动脚本、systemd 安装脚本和现有 Nginx 站点接入模板。

开发数据默认在本项目 `data/`；测试与截图在忽略目录 `output/`。FU 与共坠群星不会共用账号、世界存档或素材引用。默认服务器文件存储；对象存储适配尚未启用。

## 服务器配置

`FU_PORT` 默认 3340；`FU_HOST` 默认 127.0.0.1；`FU_BASE_PATH` 可设为 `/fu`；`FU_DATA_DIR` 与 `FU_PUBLIC_DIR` 可指定绝对目录。公开站点必须配置 `FU_CREATE_KEY`，HTTPS 接入后设置 `FU_PUBLIC_URL`。FFmpeg 可通过系统 PATH 或 `FU_FFMPEG` 指定；没有转换器时仍可上传已处理的网页音视频。

所有写操作由服务器检查，玩家看不到 GM 备注、未打开场景、预制台词和私密素材。只读预下载链接只返回 GM 明确选定的素材清单；已经下载的文件不能远程收回。世界仅存素材引用，二进制按 SHA-256 保存，登录凭据与完整备份不能公开。
