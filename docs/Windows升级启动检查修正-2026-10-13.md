# Windows 升级启动检查修正 · 0.2.2

用户在 Windows 服务器从 0.1.6 升级时遇到“新版启动检查失败”，随后回退。最初缺少服务器错误日志；现已通过用户回传的同身份诊断确认根因为父目录属性访问权限不足，0.2.2 的对应修复见末节。此前慢启动与任务等待测试只能证明升级器的其他缺陷，不能替代这个实际根因。

## 已定位的问题与处理

1. 旧升级器停止计划任务后立即继续，没有等 Windows 任务状态与原 Node 进程确认退出。现先等待退出，未退出就停止更新；回退前也采用相同处理，进程匹配限于所选部署的完整入口路径。
2. 旧检查使用固定 20 次循环。对一个延迟 45 秒后正常启动的服务，0.2.0 稳定报出同样的失败提示并回退。现按实际经过时间等待最多 60 秒，并保留最后一次连接错误或版本不匹配信息。
3. 旧脚本丢弃检查异常，回退后也不检查旧版服务。现将当前启动的日志增量、任务状态、最近运行结果及检查地址写入备份目录的 `upgrade-report.txt`；回退后验证旧版版本号与健康响应，区分“文件恢复”与“服务恢复”。
4. 后台启动原先先读取 `.env` 再建立日志，配置读取异常无法落到 `server.log`。现先建立日志，在受监测的启动步骤中读取配置。检查地址也沿用已有监听地址，兼容绑定特定本机地址的部署。

未更改世界数据格式、网页功能、原配置或运行环境。仍提供包含全部官方网页文本的保留存档升级包，操作见 [升级说明](../deploy/升级说明.md)。

定向验证包括 Windows PowerShell 5 脚本解析、任务停止状态边界、配置失败日志、正常启动入口，以及基于真实 0.1.6 发行包的正常升级、45 秒慢启动、故意启动失败并回退。后者逐文件比对世界、上传素材、服务器密钥、配置与运行环境占位文件。

结果：5 项定向测试全部通过；3 个旧版升级场景全部通过，每个场景的上述 5 类保留文件均逐字节一致。故意失败场景的报告包含注入的实际错误，并确认旧版 0.1.6 恢复响应。自动化证据存于忽略目录 `output/upgrade-016-to-0.2.1-result.json`；升级 ZIP 内 53 项清单全部通过 SHA-256 校验，不含用户数据、配置、运行环境或原始规则附件。

## 根因确认与 0.2.2 修复

用户回传的 2026-10-13 12:54（北京时间）后台诊断确认：LOCAL SERVICE 可执行 Node v24.21.0，可读 `launch.mjs`、`app/server.mjs`、`.env` 与密钥，配置解析和日志写入均通过；但 Node 对入口执行 realpath/lstat 时，在 `C:\Users\Administrator\Desktop` 返回 EPERM。程序尚未加载，因此没有 server.log。这也解释了管理员手动运行正常、服务账户运行失败的差异。

原部署向导只为 FU 目录和程序、数据授予访问权，遗漏了 Node 逐级解析安装路径时所需的父目录权限。0.2.2 在 Windows 首次部署和升级入口补上统一处理：先备份沿途父目录 DACL，再向 LOCAL SERVICE 增加仅作用于各目录本身的 `ReadAttributes, Traverse`（Windows Allow ACE 自动带 Synchronize）。不授予目录列表、文件内容读取或写入，不向子项继承，不移除已有权限。对应实现位于 `deploy/windows-common.ps1`。Node/libuv 的 Windows 路径检查会使用目录属性访问，技术依据见 [libuv 官方 Windows 文件实现](https://github.com/libuv/libuv/blob/v1.x/src/win/fs.c)。

原权限保存在升级备份内 `service-path-acl-before.json`；首次部署保存在部署目录的唯一编号文件中。修复保留原安装位置、服务身份、任务入口、数据和访问地址。程序启动失败回退时保留这项路径权限修复。用户已关闭旧进程，可直接升级，成功后仍会启动新版。

已在隔离 NTFS 目录构造两层受限父目录，重现“文件直接读取成功，但 Node 入口 lstat 报 EPERM”。应用同一权限修复后 Node 24 可正常执行；验证授权仅为目录属性与路径通过，不继承到子文件，不改变其他账户权限；重复修复不重复改变 DACL。7 项 Windows 定向检查全部通过。所有测试仅使用新建测试目录；未在本机用户桌面或系统父目录应用授权。

0.2.2 发行验证：基于真实 0.1.6 旧发行包完成旧进程已关闭、旧进程正在运行、故意启动失败后回退三种场景，全部通过。每个场景保留的世界、素材、配置、服务器密钥与运行环境文件均逐字节一致。证据位于忽略目录 `output/upgrade-016-to-0.2.2-result.json`。升级 ZIP 的 53 个清单条目全部通过散列校验，PowerShell 文件具备 UTF-8 BOM；包内不含用户数据或配置。
