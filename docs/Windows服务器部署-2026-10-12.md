# Windows 服务器部署修复 · 0.1.6

用户确认报错截图来自 Windows 服务器。旧包 Windows 入口只检查 PATH 中的 Node、固定监听 127.0.0.1、不读取 .env，也没有 Windows 后台安装流程；原“复制部署包”的 Windows 服务端交付不完整。

## 交付

- `deploy-windows.cmd` 由管理员运行，交互选择 IP 直连／接入已有站点、端口和公网访问地址。
- 安装环境优先使用现有 Node.js 22+；否则按官方 Node.js 24 LTS 的 SHASUMS256 清单下载对应 Windows 架构 ZIP，核对 SHA-256 后提取免安装运行时。运行时只在服务器保存，不进入玩家下载资源或程序更新包。
- `.env` 保留建房钥匙和其他已有配置，旧文件备份后更新相关字段。IP 直连监听 0.0.0.0；反向代理模式继续监听 127.0.0.1。公网地址不会根据内网网卡盲目猜测。
- 建立 `FabulaUltima` 开机计划任务，Local Service 权限运行 `launch.mjs --background`；世界、日志目录允许服务身份写入，前台启动脚本沿用同一个入口及配置读取。
- 直连模式只放行本程序选定 TCP 端口；不关闭 Windows 防火墙、不修改其他程序。已有同名不同目录任务／规则、其他程序占用端口时中止，不停止别的服务。云平台安全组需要管理员在云控制台放行。
- `launch.mjs` 读取 .env，后台输出写入 logs/server.log；向导在成功提示前检查本机健康接口，但不声称公网已经连通。
- 补上 HTTP + IP 环境的 UUID 生成：使用浏览器已有 getRandomValues，避免 randomUUID 仅在安全上下文提供导致建人物、命刻等操作失败。

## 验证与边界

在当前 Windows 主机执行：脚本解析、IP／域名规范化、错误地址拒绝、原配置与建房钥匙保留、PATH 不包含 Node 时从标准目录发现运行环境；实际通过 start.cmd → PowerShell → Node 启动隔离数据目录，验证 .env 的端口与 /fu 路径、建房钥匙校验以及原数据保留。HTTP 权限回归和非安全上下文 ID 测试通过，共 4 项；类型检查与生产构建通过。

实际构造并校验计划任务 Action／Settings／Local Service Principal，未注册本机开机任务或修改本机防火墙。读取官方 SHASUMS256 清单，确认 Windows x64 文件名及校验项；当前机器已有 Node，因此未为验证重复下载完整运行时。

尚未连接用户的 Windows 服务器执行安装，远程服务器的系统版本、出口网络、实际任务运行和云安全组／公网访问仍需在那里确认。部署包中使用说明已给出操作步骤与失败日志位置。
